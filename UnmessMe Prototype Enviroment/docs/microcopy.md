# Microcopy patterns (workflow-scoped reference)

> Pulled in by the assemble-screen skill when composing. Loads only when the
> workflow reaches for it (progressive disclosure).

## Casing

- Title Case for all interactive text: buttons, links, menu items. For example
  "View Dashboard", "Add New", "Read More". Keep it to 1 to 3 words.

## Primary call to action

- The primary CTA is "Unmess Me": the product name spoken back as the user's own
  command. Use it for the main conversion button (hero, footer CTA). It ties the
  action to the brand because the brand name is literally the action.

## Problem titles

- 3 to 6 words, casual, not clinical, not dramatic. Plain language.
- For example: "Behind on bills", "Sleep falling apart", "Avoiding this
  conversation".

## Step lists

- Actionable, small, realistic, with clear verbs.
- Patterns: "Start by...", "Make a tiny list of...", "Send one message to...",
  "Take 5 minutes to...", "Break this into two chunks."

## Dashboard insights

- Playful analytics tone. For example: "Your stress-heavy problems are forming a
  squad." "Here's your smallest hill to climb first." "Your brain has been
  avoiding this for 14 days, relatable."

## System status (use sparingly)

- Monospace, pseudo-code style for transitional or loading states:
  `// STATUS: [STATE] -> [ACTION]`.

## Disclaimers

- Any output referencing emotional distress carries: "This is not medical or
  professional advice." Crisis contexts also carry the emergency-hotline line.
